# Tutorial 14: First-Run Starters

This tutorial is the practical guide to Numel's first-run starter surface.

The goal is simple:

1. open an empty space
2. choose a strong starter instead of a blank canvas
3. run it once
4. continue with the next best surface for that starter

## Where The Starter Surface Appears

When the current space is still empty, Numel shows:

- an inline `Start This Space` panel in the workbench
- a first-run starter modal after login, if your user preference allows it

The first-run modal has a `Show on login` checkbox. That preference is stored per user.

## Current Starter Set

### Quick Start

Use this when you want the smallest possible runnable workflow.

What it gives you:

- a tiny starter flow
- a fast way to learn edit → save → run

Best next step:

- run it once
- then ask the Assistant to adapt it into your real first workflow

### Research Starter

Use this when you want a planner-style workflow for research and reporting.

What it gives you:

- a stronger multi-step starter than the tiny quick-start flow
- a visible research-oriented path you can refine

Best next step:

- run it
- refine it with Assistant for your own research process

### Webcam Starter

Use this when you want to try browser media input quickly.

What it gives you:

- a browser-media workflow
- a fast way to validate camera/media access locally

Best next step:

- run it once
- then tailor it for your actual capture or analysis use case

### Repo Assistant

Use this when you want an assistant grounded in the local workspace and files.

What it gives you:

- a local workspace assistant
- `workspace_toolkit` and `file_toolkit`
- a good starting point for repo inspection and file questions

Best next step:

- run it
- then refine it for the real project or repository you want to inspect

### Mini App Starter

Use this when you want something that is easy to turn into a published app.

What it gives you:

- a compact assistant workflow
- a starter shape that works well with Published Apps

Best next step:

- run it once
- refine the user-facing behavior
- open `Published Apps` and generate a standalone app from it

### Support Workbench

Use this when you want a deployment-ready support assistant.

What it gives you:

- a support-oriented linked workbench
- a strong starting point for channels, handoff, and knowledge-backed support

Best next step:

- run it
- then open `Assistant Deployments`

### Ops Workbench

Use this when you want an operator assistant that pairs well with proactive jobs.

What it gives you:

- an operations-oriented linked workbench
- a strong starting point for proactive or diagnostic assistant deployments

Best next step:

- run it
- then open `Assistant Deployments`

### Ask Assistant

Use this when you already know what you want and prefer to start from a prompt.

What it gives you:

- a direct jump into the Assistant
- a prompt-oriented path instead of a prebuilt starter

Best next step:

- describe the workflow you want
- then edit the resulting graph and run it

## Follow-Through Guide

After loading a starter, Numel shows a follow-through guide under the stage bar.

That guide points you to the next best move for the starter you loaded, such as:

- `Run Now`
- `Refine With Assistant`
- `Open Assistant Deployments`
- `Open Published Apps`
- `Browse More Starters`

## Recommended Order For New Users

If you are unsure where to start, this is a good sequence:

1. `Quick Start`
2. `Repo Assistant` or `Research Starter`
3. `Support Workbench` or `Ops Workbench`
4. `Mini App Starter`

That sequence moves from first-run success into real assistant and publishing surfaces without asking you to understand every node type up front.
